# Planned follow-ons

These are second-milestone expansions, not blockers for v0.1.0. Each should
follow the practical-corpus contract: shared source, standalone application,
native tests, catalog metadata, and a clear reason the chosen bird improves
the dataflow.

## Practical applications

### Loan or application policy selection

Use K/KI selector values, Cardinal, and configured partials to choose approval
or review policies explicitly. Contrast combinatory selection with ordinary
`if` without presenting it as the default production style.

### Feature-quality report

Fork one feature array into complementary metrics with Phoenix, use `over` for
symmetric preprocessing, and combine the results into a quality score. This
should explain why shared input/fork structure matters for ML diagnostics.

### Batch normalization pipeline

Bind normalization parameters into partials and compose validation,
normalization, clipping, and classification with B/B3 and `each`. Compare
scalar, vector, and matrix behavior and call out when native pervasion is more
appropriate than `each`.

### Ensemble score fusion

Use Psi, Phoenix, and Bald Eagle to make parallel model branches and fusion
structure visible. Start with deterministic numeric score vectors so the demo
does not require trained model artifacts.

### Callable strategy registry

Store named and configured partial policies in a record, select a policy by
business context, and invoke it through Thrush or direct `call`. Demonstrate
late binding and structural configuration without heterogeneous function
arrays.

### Recursive practical workflow

Apply the eager-safe applicative Sage to a real recursive policy such as a tree
fold, bounded retry-state evaluator, or nested rule interpreter. Include input
guards and compare clarity and cost with ordinary named recursion.

## Conceptual extensions

- Derive Cardinal, Warbler, and selected routing birds from S/K or other small
  bases, checking extensional equivalence over scalars, arrays, and callables.
- Add readable wrappers such as `compose`, `constant`, and `flip` only where a
  practical consumer proves the vocabulary useful.
- Expand the bird catalog with additional canonical families after verifying
  names, equations, saturated behavior, and staged behavior together.
- Add performance notes comparing direct calls, named birds, derived birds,
  and applicative-Sage recursion without making premature optimization claims.

## Maintenance triggers

Repeat the whole-aviary audit whenever sw-MLPL changes callable
representation, application associativity, partial equality/rendering, or HOF
dispatch. A newly supported feature moves from a precise acceptance fixture to
the native suite in the same commit that adopts it.
